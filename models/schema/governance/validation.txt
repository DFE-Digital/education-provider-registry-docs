Governance schema validation - points worth checking (not necessarily bugs)

1. Gap in the BAU role-code mapping: codes '01'-'09' then jump to '11'-'20' - '10' is
   absent from role_mapping in transforms/governance-appointment-from-bau.sql. If GIAS
   BAU StaffRole actually has a code 10, any StaffRecord using it will simply be
   excluded by the INNER JOIN dbo.StaffRole / LEFT JOIN role_mapping (silently dropped,
   no error). Confirm against the BAU StaffRole reference table that 10 is genuinely
   retired/unused.

2. Resolved: governance.governance_appointment.establishment_urn and
   establishment.establishment.urn are both integer. There remains no cross-database
   foreign key, by design, but future joins now use matching target types.

3. Hardcoded role-ID allowlists in load/load-governance-appointment-fixture.sql
   (NOT IN (1,2,3,4,5,6,7), <> 8) duplicate what the governance_role_type seed table
   already encodes. If a new role type is ever added, both the seed data and this
   loader check need updating in lockstep - easy to miss the second one.

4. governance-schema.sql has a current_database() = 'governance_local' runtime guard;
   the sibling basic-establishment-data-schema.sql in the parent schema directory only
   has a comment, no equivalent guard. Not wrong, just an inconsistency in safety-net
   rigor between the two schema scripts if you want them to match.
